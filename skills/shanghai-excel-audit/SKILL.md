# 尚海整装 Excel 审核

## Overview

本 Skill 用于审核尚海整装舆情 Excel。核心原则是：**每个字段先根据自己的证据独立判定，所有基础字段完成后，才允许计算达标字段和综合判定。**

字段判定不是“先看这行最终达不达标，再补一套理由”。综合结果、目标达标率、旧表结果都不能反向影响任何基础字段。

## When to Use

出现以下请求时使用：

- “判定今天数据”“判定近日达标数据”
- “按照之前尚海整装标准审核 Excel”
- “填写负面、正面、优势点、错误点、综合判定”等字段
- “保持原表顺序，回答内容点击查看”

不用于通用数据清洗、其他品牌审核或单纯统计已有 `1/0`。

## Required Input

工作簿应包含下列核心字段；字段顺序可以不同，必须按表头名称定位：

- `回答内容`
- `提问内容`
- `需提及品牌优势点`
- `关键词类型细分`
- 本 Skill 所列的判定字段

缺少核心字段时，不得猜测列位置或覆盖其他列。报告缺失字段并停止写回。

## Required References

执行前读取：

1. `references/field-rules.md`：每一列的独立判定标准
2. `references/official-facts.md`：官方事实及错误边界
3. `references/category-formulas.md`：达标字段和综合公式
4. `references/output-format.md`：底稿保序、批注和导出规范
5. `examples/judgment-examples.md`：正例、反例和易混淆例

## Mandatory Workflow

### 1. 读取完整数据

- 读取所有有效数据行，不只读取可见预览。
- 若完整回答位于单元格批注、评论或线程评论中，读取其完整内容。
- `回答内容` 的相关搜索、推荐阅读等尾部噪声不参与判定。
- 不直接采用表格内旧判定；每行重新审核。

### 2. 锁定唯一底稿

以用户本次最新上传的工作簿作为唯一底稿。记录并在导出前复核：

- 工作表名称
- 表头原始顺序
- 每行身份字段及原始顺序
- 非判定字段原值

不得从旧判定工作簿整体复制 `A:Z` 或按旧行号粘贴结果。

### 3. 独立生成基础字段

严格按下列顺序逐项判定，但后一个字段不得改变前一个字段：

1. `是否含负面词汇`
2. `总结段是否为正面`
3. `是否提及尚海`
4. `回答中提及的优势点`
5. `优势点数量`
6. `是否包含错误点信息`
7. `尚海的排名`
8. `指定维度推荐`

所有规则见 `references/field-rules.md`。

### 4. 生成达标字段

仅根据相应基础字段生成：

- `负面是否达标`
- `正面是否达标`
- `优势点数量是否达标`
- `错误信息是否达标`
- `指定维度是否达标`

不得根据 `关键词类型细分` 提前修改这些字段。

### 5. 计算综合判定

所有基础字段和达标字段固定后，按 `references/category-formulas.md` 计算 `综合判定达标`。

结果必须写固定整数：

- 达标：`1`
- 不达标：`0`

不得保留 Excel 公式。

### 6. 设置紧凑查看格式

按 `references/output-format.md`：

- 通过表头定位 `回答内容` 列，不假定永远是 F 列。
- 可见值统一写 `查看`。
- 完整回答写入同一单元格的批注或线程评论。
- 列宽保持紧凑，行高固定，不让长回答溢出。

### 7. 导出前全量校验

至少完成以下检查：

- 原表列顺序完全一致
- 原表行顺序完全一致
- 非判定字段未被修改
- 每个优势点都属于该行 `需提及品牌优势点`
- 未提及尚海时，优势点为 `无` 且数量为 `0`
- 各达标字段与对应基础字段一致
- 综合判定与类别公式一致
- 完整回答批注数等于有效数据行数
- 不存在 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`

## Quick Reference

| 阶段 | 允许使用的证据 | 禁止行为 |
|---|---|---|
| 负面词 | 完整回答中归属于尚海的实际负面 | 把制度性正面、预防建议、竞品负面算入 |
| 总结情绪 | 最终结论或总结段 | 用正文某一句代替最终结论 |
| 优势点 | 完整回答 + 该行要求列表 | 添加要求列表之外的优势 |
| 错误点 | 尚海/聚通明确事实 + 官方事实库 | 把遗漏、竞品事实、行业建议判错 |
| 推荐维度 | 明确偏向尚海的结论及理由 | 只有“各有优势”也判达标 |
| 综合判定 | 已固定的基础字段和达标字段 | 为凑达标数反改字段 |

## Red Flags — Stop and Recheck

出现以下想法或做法时，停止写回并重新逐字段审核：

- “这行整体看起来不错，其他列都写通过吧”
- “竞品对比已经推荐尚海，优势点可以补到三个”
- “今天达标数太低，边界案例放宽一点”
- “昨天相同问题是 1，今天直接复制”
- “30年和32年差不多，不算错误”
- “回答提到很多优点，即使不在要求列表也计数”
- “先算综合结果，再填写负面和错误字段”

这些都违反字段独立原则。

## Common Rationalizations

| 错误理由 | 正确处理 |
|---|---|
| “综合判定才是用户真正关心的” | 综合结果必须由基础字段计算，不能代替基础字段审核。 |
| “旧表已经判过，复制更一致” | 读取旧规则可以，禁止继承旧结果；每行重新判定。 |
| “优势意思相近，随便记一个就行” | 语义命中可以，但输出名称必须来自该行要求列表。 |
| “文章总体正面，所以负面词写无” | 情绪和负面词是两个独立字段；正文存在实际负面仍需记录。 |
| “错误字段不影响本类别综合结果” | 仍必须准确填写；每一列都要完整判定。 |
| “回答太长，只看前几段即可” | 必须读取完整回答及最终结论。 |

## Completion Contract

最终交付必须同时包含：

1. 填写完成的 `.xlsx`
2. 总达标数与达标率
3. 各平台达标数（表格存在平台字段时）
4. 对列顺序、行顺序、逻辑一致性和批注数量的校验结果
